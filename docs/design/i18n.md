# Interface languages

Status: rule from the first screen. English is the default and, for now, the only language.

- Every text a person reads or a screen reader announces (labels, `aria_label`, tooltips,
  placeholders, toasts, window titles) comes from `apps/cloudrs/src/i18n`, one module per area
  (`i18n::player`, `i18n::search`…). Never a string literal in a screen.
- Same approach as xemnas:
  - `strings!` generates `fn name() -> &'static str`;
  - `formats!` generates `fn name(args) -> String`, with named arguments inside the literal
    (`"{count} tracks"`) so each language can reorder them;
  - a missing translation is a compile error.
- Cost: one atomic read and a `match` per string. No allocation, map or file read at runtime.
- Content is never translated: track titles, artist names, descriptions and comments are shown
  as SoundCloud returns them.
- Dates, relative time and number formatting follow the selected language.
- The language is a saved setting (ADR 0017). `Language` lives in `sc-core` and
  `i18n.rs` re-exports it; the app calls `i18n::set` with the saved value before the window
  opens and whenever the core echoes a change.
- The picker in Settings appears with the second language. Until then it is not shown.

Adding a language: add its tag to the `Language` enum and fill in every `strings!`/`formats!`
entry. The compiler lists what is missing.

## Adding or reviewing a language

Each `strings!`/`formats!` entry has one field per language (`en:`, then `pt_br:`…). Keep every
named argument of a `formats!` entry (`{count}`, `{name}`) and the same Unicode escapes as the
English (typographic quotes, apostrophe, ellipsis).

- The compiler reports only the first missing entry in each block, so expect to rebuild several
  times; `grep -c` the entries of a module to see what is left.
- A native speaker reviews the texts before they ship.
- Texts grow about 30% in Portuguese: check truncation on buttons, pills, tooltips and the
  mini player.
- Tone: "você", short sentences, like the English.
